# UI Audit

Running log of hands-on UI findings, in the spirit of `content/audit/` but for
the app surface rather than the corpus.

Severity follows the content audit: **[blocker]** ships broken, **[important]**
noticeably wrong, **[polish]** cosmetic. Status is one of OPEN, FIXED, or
DECISION NEEDED.

## Method and environment

Manual passes driven on the `pantas_pixel` Android emulator
(`flutter run --flavor dev -t lib/main_dev.dart`), Flutter 3.44.6.

**Caveat for anyone reproducing these:** the pass on 2026-07-25 ran against a
temporary `assets/seed/v1.json` generated by `tools/build_dev_seed/` from
`content/questions/` and `content/lessons/` — 1,115 questions and 141 lessons
under a single UPCAT exam. That seed is throwaway scaffolding for UI/UX work,
not shipping content, and it breaks two expectations in
`test/core/storage/data/seeder_test.dart` that assume the 2-subject demo seed.
Findings below that depend on real content volume are marked as such.

## Findings from manual passes

### UI-001 [blocker] Screens with no back or exit control — FIXED

Reported 2026-07-25: "there are a lot of instances where I can't go back
because the back/exit button doesn't exist."

Confirmed and traced to a single root cause. `context.go()` **replaces** the
go_router stack, so the destination's `AppBar` has nothing to pop and renders
no back arrow. For routes outside the `StatefulShellRoute` the bottom tab bar
is absent too, leaving no on-screen exit at all — Android system back then
quit the app outright (verified from `/plan`).

Affected: today's session, quick quiz, retake, drill, drill-subtopic browser,
study plan, quiz results, assessment, assessment results, and — via private
`_go` helpers wrapping `router.go()`, which a `context.go(` search misses —
the entire Settings subtree plus the legal Privacy/Terms pages.

Two aggravating details:

- `quiz_page.dart` set `leading` **only** while `QuizRunning`, so the loading,
  error and empty states had no control at all. An empty drill (a topic with
  no authored questions) offered nothing but a "Retry" that could never
  succeed.
- Delete Account's "Cancel" calls `Navigator.maybePop()`, a silent no-op once
  `go()` had emptied the stack.

**Fixed** by converting those call sites to `context.push`, giving
`quiz_page` an unconditional `leading` (close-with-confirm while running,
plain back otherwise), and using `pushReplacement` for assessment → results so
back does not re-enter a completed run. The standing rule is now: navigate
outside the tab shell with `push`, never `go`; reserve `go` for tab switches
and deliberate flow resets such as `/onboarding`.

### UI-002 [polish] Elastic overscroll at the top and bottom of pages — CLOSED, NO CHANGE

Reported 2026-07-25: "when pulling down from the top or pulling up from the
bottom the page becomes elastic."

**This is current Android platform behaviour, not a defect.** The app sets no
`ScrollBehavior` or `ScrollPhysics` anywhere in `lib/`, so it inherits
Flutter's `MaterialScrollBehavior`. With `useMaterial3: true`
(`app_theme.dart:28`) on Android that resolves to:

- `ClampingScrollPhysics` — the scroll *position* stops hard at the edge, and
- `StretchingOverscrollIndicator` — the *content* stretches while you pull.

(Source: `material/app.dart:879-898` and
`widgets/scroll_configuration.dart:243-252` in the Flutter SDK.)

The stretch is what Android 12 (API 31) introduced to replace the older blue
edge glow. Google's own apps behave this way, and Flutter already picks the
correct idiom per platform automatically — iOS builds get `BouncingScrollPhysics`
rubber-banding instead, which is equally the norm there.

So the literal request — "use what the industry does" — is satisfied by
changing nothing. The real question is whether Pantas should deliberately
*deviate* from platform convention, which is a design call rather than a bug
fix:

| Option | Behaviour | Trade-off |
|---|---|---|
| **A. Keep defaults** (recommended) | Stretch on Android, bounce on iOS | Native on both; zero code; users get what every other app on their phone does |
| **B. Suppress the indicator** | `ScrollBehavior.copyWith(overscrollIndicator: false)` — hard stop, no visual | Feels tight and deliberate, suits the Ink & Rule identity; non-native, and removes the only feedback that you have reached the end |
| **C. Force bouncing everywhere** | iOS rubber-band on Android too | Consistent across platforms; actively wrong on Android and often reads as "this is an iOS port" |

If the objection is specifically that the stretch looks bad against the fixed
page headers, that is worth a targeted look before reaching for a global
override — the effect is per-`Scrollable`, so it can be tuned in one place
without changing platform behaviour app-wide.

**Decision (2026-07-25, Aedwon): option A — keep the defaults.** No code
change. Pantas follows platform overscroll convention: stretch on Android,
bounce on iOS. Do not add a `ScrollBehavior` or `ScrollPhysics` override to
"fix" this; if it comes up again, it is working as intended.

## Findings surfaced while fixing the above

Not from the manual passes; recorded here so they are not lost.

### UI-003 [important] Study plan is an unfinished feature — entry hidden

`/plan` renders "Plan unavailable: UnimplementedError: Override
studyPlanExamProvider". Both `studyPlanExamProvider` and
`studyPlanSignalsProvider` in
`lib/features/study_plan/application/study_plan_providers.dart` are throwing
stubs overridden only in tests.

Per decision on 2026-07-25 the "Study plan" row was removed from the Quiz
tab's "More practice" section rather than patching the page. The route still
exists and is deep-link reachable, and carries a working back arrow after
UI-001. Restore the row only once those providers read real data — the missing
piece is genuine (mastery computation, due-review counts, recommendations),
not wiring.

### UI-004 [polish] Latent dead end at `/wrapped/:artifactId`

`notification_tap_router.dart:63` navigates with `go()`, and
`wrapped_reveal_page` defines no `leading`. Currently unreachable, because the
wired `planReader` in `notifications_providers.dart:31` is hardcoded to
`NotificationPlanSnapshot.unavailable()`, so the route is always `/home`. This
becomes a real dead end the day Wrapped notifications are wired up.

### UI-005 [important] Inline math sits below the baseline

`portable_text_renderer.dart` renders inline LaTeX as a `WidgetSpan` with no
`alignment`, so every inline `$x$`, `$m$`, `$<$` drops subscript-low in the
middle of a sentence. Highly visible in mathematics and science lessons.
Depends on real content — invisible with the demo seed.

### UI-006 [important] Numbered solution steps all render as "1."

`portable_text_renderer.dart` clears its list counters on any non-list block.
In worked solutions a display-math block sits between each step, so every
solution reads "1. 1. 1. 1." rather than 1, 2, 3, 4. Depends on real content.

### UI-007 [important] Question stems render markdown and LaTeX literally

`question_card.dart:22` is a plain `Text`. A Filipino vocabulary item displays
`Ang **pagtitiis** niya` with the asterisks showing, and 237 questions in the
generated seed carry `$…$` LaTeX that appears raw. The v1 schema stores stems
as plain text columns with no rich-text representation, so this is a schema
question as much as a rendering one.
