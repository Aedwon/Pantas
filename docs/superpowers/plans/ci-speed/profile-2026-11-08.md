## 5 very_good test optimization (bundle all tests into one file)
- Would remove the dominant cost: 1033 suite loads (48 min of suite-time) become 1 compile per shard.
- Not installed locally (UNMEASURED). Feasibility checks: no flutter_test_config.dart, no dart_test.yaml, no @Tags/@Timeout, 1 @TestOn file, 0 Directory.current/Platform.script uses, 0 dart:html. 1034 files each define main().
- Risks (MEDIUM): global state leaking between files in one isolate: debugDefaultTargetPlatformOverride (3 files), FlutterError.onError assignment (2), HttpOverrides (1), method-channel mock handlers (11), 45 files with top-level mutable/late/final vars; setUpAll/tearDownAll in 64 files (the optimizer wraps each file in a group so scope is kept). 20 process-spawning tool tests and release_e2e_runner (uses git history) should stay outside the bundle. Relative-path file reads rely on cwd=repo root, unchanged by bundling. One big isolate also serializes what is now parallel; real gain depends on -j.
- Cheaper alternative with the same effect: shard BY FILE (list test files, split, pass paths) so each shard loads ~172 files, not 1033. Estimated shard load cost cut ~6x (ESTIMATE, UNMEASURED).
