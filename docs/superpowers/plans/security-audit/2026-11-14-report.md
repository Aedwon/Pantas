### S-12: a failed checkout creation blocks that product for the account

`functions/src/paymongoCheckout.ts` writes the reservation as `creating` before calling PayMongo.
If that call or the next write fails, nothing resets it, and every later attempt answers
"Checkout creation is pending". A transient PayMongo error can strand a paying customer.
Fix: a short lease on `creating`; after it lapses, reconcile with PayMongo by reference before
creating a new session. Fix before live keys.

### S-14: no Firestore backups

Point-in-time recovery, delete protection and backup schedules are all off on pantas-prod.
Fix: a daily backup schedule with 7-day retention and delete protection on. Cost: cents a month.

### S-16: `main` has no branch protection

No branch protection or ruleset; Actions allow any action and do not require SHA pinning.
Mitigations already in place: no Actions secrets, read-only default token, no
`pull_request_target`, one collaborator, secret scanning and push protection on.
Fix: a ruleset on `main` (no force push or deletion), third-party actions pinned to SHAs,
Dependabot alerts.

## Confirmed sound

- No secrets found in git history (all refs, regex scans by both auditors) or in the prod bundle.
- Database rules keep server-only data closed; clients cannot write Pro, entitlement, age or
  consent fields; paid content is served only from the server ledger.
- Payment webhooks verify signatures before any read, check mode, amount and currency, and
  de-duplicate events. A forged or replayed event cannot grant Pro.
- Prices match `docs/pricing.md`; the client sends only a product id.
- Admin access needs a server-set claim and is audited.
- One dependency advisory (fast-xml-parser) is not reachable; excluded.
