# Lesson Illustrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace all 279 lesson illustration placeholders with the approved mix of 189 code figures, 56 open educational assets, 23 native text or math replacements, eight cuts, and three founder-drawn assets.

**Architecture:** Both seed builders use one pure Dart Markdown parser. The parser emits `figureSpec`, `table`, `latex`, text, and image portable-text blocks. One figure registry sits behind both `QuestionFigure` and `LessonFigureWidget`, so every painter has one interface and one failure path. Open and founder assets remain under `content/illustrations/`, are uploaded to Sanity only after separate authorization, and enter lesson bodies through a committed asset map.

**Tech Stack:** Flutter `CustomPainter`, Dart, Portable Text JSON, Sanity asset HTTP API, Python content audits, TSV and YAML manifests.

**Spec:** `docs/superpowers/specs/2026-08-15-lesson-illustrations-reduction-design.md`

## Global Constraints

- The approved totals are exact: 189 code, 56 open assets, 23 native replacements, eight cuts, and three founder assets.
- Do not change the approved strategy or add a sixth strategy.
- `docs/content/illustrations/worklist.tsv` stays generated by `tools/audit/list_illustrations.py`. Never edit it by hand.
- The exact row assignment is in Appendix A. `code` means every worklist row not named by the other four strategies.
- No new package. No database schema change. Never edit generated Dart files.
- Code figures use theme ink, paper, faint rule, and board colors. They never hardcode black or white.
- Code figures follow Ink and Rule: hairlines, rectangles, no shadows, no decorative color, and no large radii.
- Every code figure carries a plain semantics label. Bad JSON, a missing required field, or an unknown kind draws the existing visible missing-figure box.
- Never add a number or label that the marker or lesson does not state.
- Open assets come only from the approved source families. Every asset records its source page, direct download URL, license, creator or agency, credit line, and SHA-256 digest.
- Open assets are PNG, 1600 px wide, on `#FAFAF7`, and aim below 300 KB. Do not stamp third-party work as Pantas copyright.
- Founder assets use the three exact target paths and briefs from the spec. No worker generates them.
- No em dashes. Use American spelling. User-facing text stays grade-5 simple.
- Ignore demo work. Do not fix or reformat demo files while doing this plan.
- Full emulator screenshots are forbidden. Aedwon performs the light and dark visual check.
- Before each Gemini wave, ask Aedwon how much Gemini remains and confirm whether the percentage means remaining or consumed. State the model and the reason. Below roughly 25% remaining, run one worker at a time and do not start a batch that may be stranded.
- Gemini 3.7 Flash High implements settled batches. Gemini 3.1 Pro High verifies each Flash wave and never edits. Codex owns integration, conflicts, external-mutation checks, and final verification.
- Each worker reads `AGENTS.md`, `SUBAGENTS.md`, this plan, the spec, and `docs/superpowers/2026-08-04-execution-pipeline.md` Part 9 in full. Each worker gets a new worktree. Do not use or clean the existing `wt-m7`, `wt-s4`, or unregistered `nb-s3` trees.
- Branch, worktree, commit, merge, and Sanity upload steps require Aedwon's explicit authorization. Never push.
