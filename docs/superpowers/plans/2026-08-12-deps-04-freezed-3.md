> **How to work this plan.** Task by task, in order. Commit the moment a task's
> own check passes, before starting the next one.

> **Required reading before Task 1:** `AGENTS.md` in full.

> **Follow the plan. Do not redesign.** If a step is ambiguous or looks wrong,
> **stop and say so.**

**Goal:** Move `freezed` to 3.x. It is the one package standing between this
repo and the encryption group, which has been blocked twice already.

**Tier:** Pro. Ten files, and a wrong migration breaks generated code
everywhere at once.

## Why this unblocks so much, checked by resolving it 12 August

`drift_dev` 2.34 needs `build` 3 or newer. `freezed` 2 pins `build` to 2. So
drift, `sqlite3` and the whole encryption change sit behind this one bump.

**Riverpod 3 was thought to be in that chain and is not.** The blocker was
`riverpod_generator`, and **nothing in this repository uses it**: there is not a
single `@riverpod` annotation in `lib/`. It and `riverpod_annotation` are
declared and unused. **Removing them is what clears the path**, and Riverpod
itself stays on 2.x in this plan. Do not touch it.

**Verified by resolution before this plan was written**: freezed 3 plus the two
removals plus drift 2.34, `sqlite3` 3.5 and no `sqlcipher_flutter_libs` all
resolve together.

## Task 2: The ten models

**What freezed 3 changes**, and read its changelog before you start:

- A class using `with _$X` must now be declared `abstract` or `sealed`. Plain
  `class X with _$X` no longer generates what it used to.
- Unions become `sealed`.

**Do this one file at a time**, in the order listed above, running the generator
after each. Do not batch ten files and then generate.

```bash
dart run build_runner build --delete-conflicting-outputs
```

**Rules:**

1. **Field lists, defaults, `@Default` values, JSON keys and factory names stay
   byte for byte the same.**
2. **If a file needs anything beyond adding `abstract` or `sealed`, stop and
   report it** before doing the rest. That would mean the migration is not what
   this plan says it is.
3. **Never hand-edit a `.freezed.dart` or `.g.dart`.**

- [ ] **Step 2: Run that model's own test if it has one**

## Task 3: Prove the shapes did not move

**File:** `test/core/storage/domain/model_json_roundtrip_test.dart` (create if
absent)

**The risk in this migration is silent.** A model that generates cleanly and
serializes one key differently breaks the seed, sync and every stored attempt,
and nothing about it looks wrong.

Write a test that, for **`Exam`, `Question`, `Choice` and `Attempt`**, builds an
instance, converts it to JSON, reads it back, and asserts the round trip is
equal. Assert the **exact key names** for at least one model, so a renamed key
fails loudly.

If a model has no `fromJson`, skip it and say so in your report.
