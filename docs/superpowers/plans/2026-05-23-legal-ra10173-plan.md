# Spec 10 Legal + RA10173 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the v1 Legal + RA10173 trust surface: Sanity-ready legal pages, DPO contact details, verified account deletion flow, Cloud Function/rules guardrails, and documentation without implementing Spec 11 Progress or v1.1 FCM/server push.

**Architecture:** Legal content is a small feature surface routed at `/legal/:doc`, backed by an app-local fallback provider now and shaped so a Sanity legal-document source can replace it without a route or UI rewrite. Account deletion reuses the existing Settings + AuthRepository seams and the existing `deleteAccount` callable, while tests tighten the required behavior. In-app export is not added in v1 because Spec 8 explicitly downgraded portability to DPO email; the existing `exportData` callable remains a scaffold parked for v1.x and guarded against accidental product exposure.

**Tech Stack:** Flutter, Riverpod, GoRouter, widget tests, tool/static guardrails, Firebase Cloud Functions v2 static tests, Firestore rules static tests.

**Target spec paths:** `docs/superpowers/specs/2026-05-16-mvp-roadmap-design.md` Spec 10, `docs/superpowers/specs/2026-05-16-firebase-auth-design.md`, `docs/superpowers/specs/2026-05-22-settings-account-design.md`, `docs/superpowers/specs/2026-05-22-notifications-fcm-design.md`.

**Date:** 2026-05-23.

**Size:** M, matching Spec 10 roadmap sizing.
