## Seam for the seed writer and package builder (F2 builds it, not this run)

- Input is the export's `problemTypes: [{question, free, pro}]` plus `mergedQuestionActivity: {sourceId: isActive}`. `question` fields: id, lesson, topic (topic id), keyPoint, difficulty, exams (final D-P1 tags), mockExams, type, language, questionVersion, isActive, variantCount, choiceKind, showQuestionFigure, mergedQuestions [{id, variantIndex}]. `free` is the whole Free variant payload (id, exams, variants[]), `pro` is {rationales: {"<variantIndex>": [null | note per choice position]}}.
- The native `question` list already carries each merged source with `isActive` = the L2 value, so the seed writes them with no code change. The seed writer needs to: insert one content_questions row per type (type id, lesson, topic, keyPoint, exams through the exam link table, isActive, variant count, mergedQuestions JSON, choiceKind, showQuestionFigure, difficulty, type) and store `free` and `pro` as protected variant payloads keyed by type id, all in the seed transaction, with the schema from F2's Drift 11 to 12 change. The package builder then needs the matching schema version and the installer the same bump (R3).
- Release order warning: with F1 alone, the native `question` list has the 28 sources inactive and no type rows are seeded, so a seed or package built from F1 alone would hide those 28 questions. Build seeds only after F2 lands the type rows.
